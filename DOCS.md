# Документация по коду NSPD Bot

## Структура

```
bot.py                  точка входа (python bot.py)
start_bot.bat           запуск под Windows: venv, зависимости, авто-перезапуск
config.example.env      пример настроек
nspdbot/
  config.py             настройки из .env (Settings, load_settings)
  cadastral.py          распознавание и нормализация кадастровых номеров
  models.py             NspdObject: разбор ответа НСПД, тип объекта, все поля
  nspd_service.py       асинхронный доступ к НСПД: кэш, повторы, лимит параллельности
  formatting.py         карточки, связанные объекты, предложения инвесторам, CSV
  handlers.py           обработчики команд, текста и inline-кнопок
  activity.py           читаемый журнал действий для консоли, счётчики, часовая сводка
  offer_form.py         анкета предложения: вопросы, варианты ответов, состояние
  app.py                логирование, сборка Application, запуск polling
tests/
  test_bot.py           unit-тесты (stdlib unittest)
  fixtures/*.json       реальные ответы НСПД: участок, здание, квартира, машино-место
```

## Поток обработки

1. `handlers.text_handler` извлекает из сообщения все номера (`cadastral.extract_kad_numbers`).
2. Один номер: бот отправляет статус «Запрашиваю…» и потом **редактирует** это же сообщение в карточку. Несколько номеров: бот присылает сводку и CSV-файл.
3. `NspdService.get_object`:
   - отдаёт объект из TTL-кэша, если он там есть; результат «не найден» кэшируется на 5 минут;
   - объединяет одновременные запросы одного номера в один;
   - делает один HTTP-запрос `search_by_cadastral_number` (раньше их было два, со связанными объектами);
   - при таймаутах и 5xx повторяет запрос с паузой, а 404 не повторяет.
4. `NspdObject.from_response` определяет тип по `categoryId`:
   36368 ЗУ, 36369 здание, 36383 сооружение, 36384 ОНС, 37163 помещение, 37159 машино-место.
   Поля разных типов (`specified_area` / `build_record_area` / `area`, `status` / `common_data_status` и т. д.) сводятся к единым свойствам.
5. Связанные объекты запрашиваются только по кнопке (`NspdService.get_related`). Для помещений используется `parent_cad_number` из ответа, без лишнего запроса.

## Callback-данные кнопок

`<действие>:<кадастровый номер>`, где действие: `card`, `rel`, `ref`, `loan`, `loan1`, `loanm`, `plcancel`, `buy` или `json`.
Номер передаётся в самих данных кнопки, поэтому кнопки работают и после перезапуска бота.

## Займ под залог нескольких объектов

1. Кнопка `loan` спрашивает «Один объект / Несколько объектов».
2. `loan1` сразу формирует обычное предложение (`format_offer`).
3. `loanm` и команда `/pledge` записывают в `chat_data["pledge_pending"]` список номеров (с текущим объектом или пустой).
4. Пока ключ есть, `text_handler` передаёт сообщение в `_finish_pledge`. Тот объединяет номера без дублей, запрашивает их параллельно (`_fetch_many`) и отправляет `format_pledge_offer`. Длинный текст делится на сообщения по границам объектов (`split_message`).
5. `/cancel` или кнопка «Отмена» (`plcancel`) сбрасывают режим.

## Анкета предложения

- Вопросы описаны в `offer_form.py`: `LOAN_QUESTIONS`, `BUYOUT_QUESTIONS`. Вопрос «Зарегистрированные лица» задаётся, только если среди объектов есть помещение.
- Анкету запускают `loan1` и `buy` (один объект) и `_finish_pledge` (несколько). Состояние `OfferForm` хранится в `chat_data["offer_form"]`, поэтому анкета переживает перезапуск бота.
- Пока анкета открыта, `text_handler` считает любое сообщение ответом на текущий вопрос.
- Кнопки: `fo:<шаг>.<вариант>`, `fs:<шаг>` (пропустить), `fb:<шаг>` (назад), `ff:<шаг>` (остальное заполню сам), `fx:-` (отмена). Номер шага в кнопке защищает от нажатий на устаревшие вопросы.
- После ответа с вопроса снимаются кнопки и дописывается ответ. В конце `format_offer` и `format_pledge_offer` получают `answers`, а неотвеченные графы остаются `______`.
- Новый вопрос добавляется так: добавьте `Question` в нужный кортеж, затем выведите графу через `_field(answers, key, label)` в `formatting.py`.

## Журнал в консоли

- `track_update` (группа `-2`, раньше всех) запоминает, кто прислал обновление, в `ContextVar`. У каждого обновления своя asyncio-задача, поэтому при одновременных запросах имена не путаются. Здесь же пишутся команды и строка «НОВЫЙ».
- Обработчики вызывают методы `Activity` (`lookup`, `batch`, `offer`, `pledge`, `action`…). Объект хранится в `bot_data["activity"]`.
- Консольный обработчик пропускает только логгер `nspdbot.activity` и записи от WARNING (`ConsoleFilter`) и выводит их как `ЧЧ:ММ:СС  МЕТКА  текст` (`ConsoleFormatter`). Запись с `extra={"console": False}` попадает только в файл: так трассировки ошибок не засоряют консоль.
- Раз в час фоновая задача печатает `СВОДКА`, при остановке `post_shutdown` печатает `ОСТАНОВКА`.

## Доступ

Если задан `ALLOWED_USERS`, в группе `-1` регистрируется `access_guard`. Он останавливает обработку для посторонних и сообщает им их Telegram ID.

## Расширение

- Новое поле НСПД: добавьте свойство в `NspdObject`, затем выведите его в `formatting.format_card` и в `CSV_COLUMNS`.
- Новый тип объекта: добавьте `categoryId` в `_CATEGORY_KINDS` и подпись в `_KIND_LABELS`.
